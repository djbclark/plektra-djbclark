# Set up guided Plektra QA

Run these steps from the Plektra checkout. The harness lives in `qa/` and tests actual Android keyboard input with a person holding the phone. For automated Android input replay, use [Plektra's input flows](../docs/testing/input-flows.md).

1. **Check the host and device.** Confirm that `qa/Justfile` and `qa/suites/harness_demo.yaml` exist. Check for `uv`, `just`, and `adb`, plus `scrcpy` and `ffmpeg` for recording. Install missing tools using the host's package manager. Pick the operator's authorized developer phone from `adb devices -l`. Resolve its target locally, and pass `-s` with that target to every device-changing ADB command.
2. **Check Plektra.** Verify that the selected IME belongs to the debuggable Plektra build you intend to test. Use the package-manager listing and `adb -s <target> shell settings get secure default_input_method` to identify the package. Check that `adb -s <target> shell run-as <package> id` succeeds. If a debug build is needed, use the checkout's documented build and install route. On a signature mismatch, report the APK and error to the operator before taking any further install action.
3. **Set up the phone tools.** Reuse a working FIRERPA setup if available. Otherwise use the [FIRERPA setup](firerpa-hitl.md#1-install-and-configure-the-users-device-over-adb) on the confirmed test phone. Install the [HITL overlay APK](overlay-app/README.md#install), version 0.4.1 or later, and check its draw-over-apps permission. The APK is a companion to the harness and can use any test keyboard. For narration, use [an available host voice](README.md#2-what-you-need).
4. **Configure and verify.** Use [`.env.example`](.env.example) and [one-time setup](README.md#3-one-time-setup). Set `ADB_TARGET` and `PLEKTRA_QA_PACKAGE` for the selected handset and IME. Configure `FIRERPA_HOST`, `FIRERPA_PORT`, `FIRERPA_VERSION`, and the certificate path `FIRERPA_CERT` from machine-local configuration. Keep the certificate outside the checkout and keep device configuration in the environment or gitignored `qa/.env`. If the host uses a secret manager, resolve managed values there. Run `just --justfile qa/Justfile qa-connect`. Report readiness when the authenticated connection reports the expected FIRERPA version and the app and overlay checks above pass.
5. **Smoke-test after the operator says they have the phone.** Tell them the demo records the screen, prompts, keys, and touches by default. Run `just --justfile qa/Justfile qa-demo` and wait at the start card. **Done** starts with recording and **No rec** starts without it. Use only the synthetic inputs in the demo. Read the run summary and confirm the handback. For a recorded run, report the MP4 path and [check the video](README.md#check-the-video). The smoke test passes when all seven trials pass and the harness hands the phone back.

If the phone is unavailable, report the host checks and any missing device checks. For a real QA request, use [the suite workflow](README.md#4-run-a-suite) after setup passes.
